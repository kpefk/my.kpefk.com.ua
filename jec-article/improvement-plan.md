## WP1. Формалізація моделі та алгоритмів (Розділ 3 → "Model and algorithms")

1. **Формальна модель даних.** Визначити шари як кортежі/відношення: Curriculum C=(P,f,b,y), Version V, Term τ=(c,s,e,h,ctrl), WorkingCurriculum W=(V,year), Assignment A=(W,τ,g,t_primary), Lesson λ=(A,kind,sg,h,t_override). Ввести effectiveTeacher(λ)=t_override(λ) ?? t_primary(A(λ)) як рівняння (1).
2. **Нумеровані рівняння норм** з `teacher-load.formulas.ts` — кожен пункт Наказу №686 як формула: (2) семестровий контроль, (3) усний/письмовий екзамен, (4) контрольні роботи, (5) керівництво практикою, (6) курсові, (7) дипломний пул 16/|S|, (8) ліміт L(t)=round(720·rate(t)).
3. **Псевдокод:** Algorithm 1 — GenerateDraftAssignments (зі збереженням призначень через словники savedPrimary/savedOverride); Algorithm 2 — ConfirmByOrder (C0→C1→софт-правила→атомарний перехід); Algorithm 3 — AnnualHours(t) (агрегація по всіх WC року + дипломне керівництво).
4. **Аналіз складності:** генерація O(T·(G+K)) за термами T, групами G, видами занять K; пам'ять O(T·G·K); перевірка ліміту O(Λ) за всіма lesson-рядками року; довести ідемпотентність генерації щодо кадрових рішень.
5. **Інваріанти та властивості (міні-теореми):** I1 — після успішного confirm ∀t: H(t) ≤ L(t); I2 — опублікована версія незмінна ⇒ будь-який наказ відтворюваний з V; I3 — revoke∘confirm повертає стан призначень. Доведення — 3–5 абзаців, без надлишкового формалізму.

**Артефакти в коді:** нічого нового писати не треба — формалізуємо наявне; звірити кожну формулу з `teacher-load.formulas.spec.ts`.

## WP2. Емпіричний розділ (найбільший розрив) — новий Розділ "Experimental evaluation"

**E1. Масштабованість генерації та підтвердження.**
- Скрипт-генератор синтетичних робочих планів: T ∈ {10², 10³, 10⁴, 5·10⁴} компонент-термів, G ∈ {5, 20, 50} груп.
- Метрики: час generate, час confirm-валідації, пікова пам'ять; ≥30 повторів на точку.
- Подання: log-log графік час–T, таблиця mean ± SD + 95% bootstrap CI; перевірка лінійності регресією.

**E2. Ефективність валідації на реальних даних.**
- З продуктивної БД (анонімізовано): кількість спрацювань C0/C1 та кожного софт-попередження за 1–2 планувальні цикли; розподіл річного навантаження викладачів відносно L(t) (box-plot з лінією 720·rate).
- Якщо збереглися довоєнні/минулорічні ручні відомості — порівняння: час формування навантаження вручну vs у системі, кількість виявлених перевищень ліміту. Парний Wilcoxon signed-rank (не t-test, вибірка мала) + розмір ефекту.

**E3. Edge-стійкість (прямий місток до скоупу JEC — аналог "resource-constrained" у зразка).**
- Виміряти footprint стеку (NestJS+PostgreSQL+Redis) на скромному сервері: RAM/CPU у простої та під генерацією; холодний старт.
- Симуляція відмови EDBO: відключити мережу на k ∈ {1, 3, 7, 30} діб (зсунути SyncState-курсор), підтвердити повну працездатність усіх функцій розділу 3, виміряти час реконсиляції після відновлення vs обсяг накопичених змін; показати роль 10-хвилинного overlap-вікна (відсутність втрат записів).
- Це перетворює edge-абзац зі вступу з риторики на вимірюваний результат — критично для scope-fit.

**Статистика — чесна, не карго-культ:** описові статистики + bootstrap CI всюди; Wilcoxon/Mann–Whitney для порівнянь; регресія для масштабованості. MANOVA, як у зразку, тут незастосовна — не імітувати.

## WP3. Структурні розділи за зразком

1. **"Novelty of this work"** (підрозділ 2.2): нумеровані внески — (i) перша формалізована модель версіонованих навчальних планів для фахової передвищої освіти; (ii) алгоритм генерації з доведеною ідемпотентністю; (iii) машинна перевірка Ст. 60 / Наказу №686 як транзакційний інваріант; (iv) емпірична оцінка на продуктивних даних + edge-стійкість.
2. **Порівняльна таблиця систем** у Related work: 5–7 EMIS/ERP (feature matrix: версіонування планів / статутна валідація / SoD-workflow / офлайн-автономність) — жодна не покриває всі чотири.
3. **"Practical applications"** перед Conclusions: тиражування на ~700 коледжів сектору, інтеграція з розкладом, друк відомостей.
4. **Рисунки (≥6):** (1) ER-діаграма трьох шарів; (2) діаграма станів DRAFT→CONFIRMED з правилами; (3) sequence-діаграма generate→appoint→confirm; (4) log-log масштабованість; (5) box-plot навантаження vs ліміт; (6) реконсиляція після відмови EDBO; (7) розподіл спрацювань попереджень.
5. **Data & code availability:** анонімізований датасет + скрипти експериментів на Zenodo (DOI); код — AGPL-3.0 репозиторії (посилання додати після деанонімізації).
